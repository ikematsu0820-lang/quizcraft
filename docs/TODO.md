# 次にやること（商用化に向けて）

2026-11 時点のまとめ。上から順に進める。

## 公開前に必ずやること

1. **ログイン**
   - 司会者・作る人: Google ログイン（会社アカウントで使えない人がいれば、メールのリンクでのログインも検討）
   - 回答者: Firebase の匿名ログイン（画面は今まで通り「部屋コード＋名前」で参加。Google アカウントは不要）
2. **データベースの決まり（`database.rules.json`）を作り直す**
   - 今はルーム・セット・番組とも、誰でも読み書きできる設定になっている
   - 自分のセット・番組しか読み書きできないようにする
   - ルームの進行（status）は、そのルームの司会者だけが書ける
   - 回答者は、自分の欄（答え・早押し）しか書けない
   - 値の型や大きさを決まりで制限する
   - できれば App Check も入れる
3. **今のデータの引っ越し**: 番組IDで保存しているセット・番組を、ログインしたアカウントに引き継ぐ

## 公開までにやること

4. **開発用と本番を分ける**
   - Firebase プロジェクトを2つにする（開発用は新しく作る。作成は持ち主の Google アカウントで操作が必要）
   - 流れ: 開発用ブランチに push → 開発用サイトで試す → OK なら main に合流して本番
   - 今は main に push すると、すぐ本番に反映される
   - 小さい直しはすぐ本番、大きい変更だけ開発用で試す、という使い分けもあり
5. **自動テスト**: 手元の偽データベース（fakefb.js）を、Firebase 公式のエミュレーターに置き換える。主な流れと、データベースの決まり（他人のデータを触れないこと）を、push のたびに GitHub Actions で確認する
6. **本番中の安定性**
   - 司会者・モニター・回答者の再接続（回線切れ・再読み込み）を一通り確認する
   - 回答者が同じ名前で入り直したら、前の得点を引き継げるようにする（匿名ログインの番号は、ブラウザのデータを消すと変わるため）
7. **人数の確認**: 30〜100人で、早押しの順番や遅れを測る
8. **画像の置き場所**: 背景・ロゴ・問題の画像は今は data URL でデータベースに入っているので、Storage に移す（通信量とお金の対策）
9. **エラーの把握**: エラーを集める仕組み、使われ方の計測を入れる

## お金を取るなら

10. 利用規約・プライバシーポリシー・特定商取引法の表示、料金プランと決済、人数などの上限、問い合わせの窓口、使い方の説明、実際のイベントでの試験運用

## デザインまわりの残り

- 問題文・選択肢などを自由に動かせる配置（今はロゴとすみの文字を四すみに置けるだけ）
- ゲーム画面（パネル・陣取り・ブラックジャックなど）の直書きの色を、テーマの値（`--th-*`、theme_presets.js `tokens`）に置き換える
- 画面全体基準の大きさ（vh、viewer.js に約200か所）を、モニター基準（cqh）に置き換える（作成画面のプレビューと本番で比率がずれないように）
