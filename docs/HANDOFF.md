## アプリの一言説明

QuizCraft は、社内イベントや身内の集まりで「テレビのクイズ番組のような進行」をするためのWebアプリ。

- **司会者**: 問題セットを作って進行する。スマホでもPCでも使える。
- **モニター**: 会場の大画面に映す。16:9。
- **解答者**: 自分のスマホから部屋コードで参加して答える。

バニラJSの1ページアプリ（`index.html`）で、データは Firebase Realtime Database に置いている。

## 持ち主の好みと、作業の約束

- **返事**: 日本語で、平易に、短く。専門用語やコードの名前は、必要なときだけ。
- **反映**: 変更は `main` に直接コミットして push する。GitHub Actions がそのまま本番（Firebase Hosting）に出す。開発用と本番の分離はまだ無い（TODO.md の4）。
- **キャッシュ対策**:
  - `index.html` の `<script src="x.js?v=N">` と `<link href="x.css?v=N">` の数字を、変えたファイルの分だけ1つ上げる。
  - 返事では「再読み込みして」と添える。持ち主はスマホで確かめることが多く、古いキャッシュが残りやすい。
- **見せて確かめる**:
  - 直したら Playwright で画面を撮り、自分で見てから送る（`SendUserFile`）。
  - 確かめられなかったことは、確かめていないとはっきり書く。
- **選べない物の扱い**: 灰色で出さずに、出さない。理由が要るときだけ1行で添える。
- **ルールの相性**（rule_engine.js が正）:
  - 「指名」と「順番」は、どの形式でも同じ扱い。片方だけ外さない。
  - 多答では早押しを使わない。
  - 選択式・並べ替えでも早押しを使わない（全員で答えて、早い順に高得点にする）。
- **絵文字・ブラウザ標準のポップアップ**: 使わない。
  - 絵文字の代わり: `icons.js`
  - ポップアップの代わり: `dialog.js` の `App.Dialog`
- **番組のまねはしない**: 実在の番組の名前・見た目・演出は再現しない。仕組みだけを参考にする。
- **言葉**: DESIGN.md の「言葉の決まり」に従う。持ち主は、ひらがなの直訳調（「だれが答える」「全員で」）を「AIっぽい」と感じる。ただし難しい熟語を重ねすぎるのも嫌う。

## 画面を確かめる方法（要約。詳しくは ARCHITECTURE.md）

- `dev/fakefb.js` は、メモリ上の偽の Firebase。Playwright の `addInitScript` で読み込むと、ネットにつながず全部の画面を動かせる。本物と同じく、`undefined` を書くとエラーになる。
- `dev/tests/*.js` は確認用のスクリプト。`node dev/tests/viewer_reveal.js` のように動かすと、`dev/tests/out/` に画面写真が出る。
- Chromium は `/opt/pw-browsers/chromium`、Playwright は `/opt/node-tools/node_modules/playwright` にある（クラウドの作業環境の場合）。
