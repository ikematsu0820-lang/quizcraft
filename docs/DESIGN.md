# 設計思想

## 1. 何のための道具か

- **主役は「本番の進行」**: 司会者が迷わず進められ、会場のモニターが番組らしく見え、解答者が自分のスマホで迷わず答えられること。
- **作るのは手早く、細かく遊びたい人には奥まで**:
  - 最初は「形式 → ルール設定（遊び方）」の2手で始められる。
  - 細かい設定は「詳細設定」やタブの奥に置く。
  - 「シンプルに作りたい人」と「細かく作り込みたい人」の両方を満たす。
- **矛盾しない組み合わせだけを出す**:
  - ルールの相性は `rule_engine.js` に1か所でまとめる。作成画面・司会者画面・番組設定は、すべてそこを見る。
  - 選べない物は出さない。出すと「なぜ押せないのか」で迷うため。
- **見た目は「番組の見た目一式」で選ぶ**:
  - テーマ1つで、背景・枠・選択肢・正解の色・書体・文字の飾りがそろう。
  - そのあとで個別に変えた所だけが、テーマから上書きされる。

## 2. 三つの画面の役割

| 画面 | 誰が・どこで | 大事にすること |
|---|---|---|
| 司会者（host） | 司会者のスマホ／PC | 次に押すボタンが常に1つ大きく見える。判定は親指の位置に大きな〇✕。「1つ戻る」で何でも取り消せる。本番中に使わない部品は出さない（待合室では部屋コード・QR・参加者だけ）。 |
| モニター（viewer） | 会場の大画面（16:9） | テーマの色・書体で、全部の画面（タイトル・問題・正解表示・正解者発表・解答オープン・得点・順位・脱落）を統一。大きさは枠の高さ基準（cqh）。 |
| 解答者（player） | 参加者のスマホ | 今の状態（待機中／あなたの番／締め切り）を大きく。押す・選ぶ・書くの操作は1つに絞る。テーマの書体とアクセント色（スイッチで切れる）。 |

作成画面のプレビューは、モニターと同じ描画関数を使う（`App.Viewer` の `renderQuestionLayout` など）。プレビューで見えたものが、そのまま本番に出る。

## 3. 作成画面の構成

```
メニュー → 形式を選ぶ → ルール設定（解答権・解答形式・配点）→ 問題を書く画面
                                                   ├ セットの設定（一覧）
                                                   │   ├ ルール: 解答方式／正解時／誤答時／勝敗／時間／結果発表
                                                   │   ├ デザイン: テーマ／判定演出／正解表示／音・演出
                                                   │   └ 問題: 別のセットから取り込む
                                                   └ 問題ごと: この問題のデザイン（テーマ・正解の表示方法）／解説・正解率
```

- **ルール**（ルールのシート）のタブ: 解答／配点／誤答／勝敗／時間
  - 一番上に「今のルール」として、今の設定を1つの文にして出す（`rule_engine.js` の summary）。
- **デザイン**（デザインのシート）のタブ: テーマ／文字／部品／正解表示
  - 「音・演出」は別の行から開く（サウンド／演出）。
- **置き場所の考え方**
  - 得点や進行に関わること（勝敗・結果発表・解答者の端末の得点）は**ルール**に置く。
  - モニターの見え方（正解の出し方・判定の演出・正解者名を添えるか）は**デザイン**に置く。
  - 正解表示の値は `currentConfig` に入っているが、画面としてはデザインに置いている。
- **問題ごとの設定**は、セットの値の上書き。
  - 空なら「セットと同じ」。たたんで出し、値が入っている時だけ開いておく。
- **スマホとPC**
  - スマホ（1023px以下）は、一覧 → 1問の入力 → プレビュー。
  - PC（1024px以上）は3列（一覧／16:9プレビューに直接入力／設定）。
  - 呼び名とボタンの動きは、PCとスマホで同じにする。

## 4. 言葉の決まり

持ち主が「直訳っぽい」「AIっぽい」と感じる言い回しを避ける。一方で、難しくしすぎない。

1. **見出し・ボタン・選択肢は名詞で止める。** 「〜で」「〜に」「〜して」で終えない。
   - ×「全員で」「順番に」「指名して」
   - ○「一斉」「順番」「指名」
2. **クイズ番組の用語を使う。**
   - 例: 解答権、解答形式、誤答、一斉、指名、勝ち抜け、正解表示、配点、勝敗、判定演出
3. **「〜してください」をやめる。**
   - ×「遊び方を選んでください」
   - ○「ルール設定」
4. **難しくしすぎない。**
   - 熟語を重ねすぎない（「同じ点」「早い順に高得点」はそのまま）。
   - 説明文（選択肢の下の小さい字）は、ふつうの文でよい。
5. **言葉をそろえる。**
   - 「解答」に統一する（「回答」は使わない）。解答者、解答時間なども同じ。
   - 同じものに複数の名前を付けない。
6. **英語・略語を混ぜない。**
   - ×「SE」「TOP10」
   - ○「ボタン音」「早い順10人」
   - 例外: BGM は、そのまま通じるので使ってよい。

主な呼び名（今の正）:

| 物 | 呼び名 |
|---|---|
| だれが答えるか | **解答権**: 早押し／一斉／順番／指名 |
| どう答えるか | **解答形式**: 口頭／手書き／ボタン |
| 遊び方（解答権×解答形式の組み合わせ） | 作成画面上部の札は「ルール」、一覧の行は「解答方式」 |
| 正解した人への点 | **配点**: 同じ点／早い順に高得点／ヒントが少ないほど高得点／先着 |
| 間違えた時 | **誤答**: 誤答時の問題（継続・終了）、誤答者（ペナルティ）、他の人の押し順 |
| 勝ち方 | **勝敗**: 得点制／サバイバル／勝ち抜け／タイムレース（陣取りはパネル数） |
| 時間 | ① 制限時間（なし／1問ごと／セット全体／1人ずつ）② 解答時間（押してから◯秒） |
| 見た目 | **デザイン**（「見た目」とは呼ばない） |
| 正解を出すこと | **正解表示**。判定の瞬間の演出は**判定演出** |
| 問題文の上の小さな見出し | **見出し**（ジャンル名など。「タイトル」とは呼ばない） |

ここ以外の言葉は、`docs/` に無いので画面から拾って確かめる（words の一覧の作り方は ARCHITECTURE.md）。

## 5. 見た目の決まり（作成画面・司会者画面）

- **放送卓（スイッチャー）風**: 炭色（`#16161a` / `#1b1b20` / `#09090b`）と、アンバー（`#f59e0b`）。
- **区切りは塗りの濃淡で付ける**。枠線や入れ子の枠を重ねない。選んでいる物は、アンバーの細い線か文字色で示す。
- **まとまりごとに、かたまり（カード）を分ける**。セットの設定の一覧や、正解表示の「判定演出／正解表示」など。
- **入力欄**:
  - 長い文が隠れないよう、文字量に合わせて縦に伸びる（`textarea.grow-ta` と `App.GrowText`）。
  - Enter は改行ではなく、次の欄へ移る。
  - スマホでは16px以上にする（iOS が画面を勝手に拡大するのを防ぐ）。
- **下に固定したバー**（スマホ）: プレビュー・セットの設定・追加して完了・追加して次へ。
  - ダイアログは、このバーより上に出す。
- **押すと画面がずれる作りにしない**。切り替えは、影響する欄の上に置く（例: 見出しの切り替えは「問題文」の横）。
- **確認・お知らせ・入力**は、画面の中のダイアログ（`App.Dialog`）で出す。

## 6. モニターのデザインの仕組み

- **テーマ**（`theme_presets.js`）
  - 現在のテーマ: シンプル／スタジオ／ゴールデン／ネオン／ポップ／レトロゲーム／クリーン／おもちゃ箱／新聞記事／学校
  - テーマを選ぶと `currentDesign` に色・書体・文字の飾りが書き込まれる。
- **テーマの値（CSS変数）**: `Themes.setTokens` が、モニターの入れ物に `--th-*` を付ける。どの画面もこの名前で色を取り、未設定なら各画面の元の色に戻る。
  - `--th-bg` 背景／`--th-text` 文字／`--th-panel` 面／`--th-line` 線／`--th-accent` アクセント（`--th-on-accent`）
  - `--th-good` 正解の色（`revealBgColor`、無ければアクセント）／`--th-bad` 外れの色（`wrongColor`）／`--th-card` 選択肢の面
- **大きさの単位**: モニターは `#viewer-content` が `container-type:size` なので、`cqh`／`cqw` で書く。`vh` はプレビューとずれるので、新しく書かない（古い所は TODO）。
- **テーマ固有の形**: `style_common.css` の `[data-theme-id="newspaper"]` などで書く。
  - 優先度で負けるときは、属性セレクタを重ねて強くする（例: 新聞記事）。
  - `panel_board.css` は後から読まれるので、同じ強さなら勝つ。
- **文字の飾り**（`TEXT_FX`）: テロップ／金文字／ネオン／ポップ／立体。問題文・選択肢・第◯問それぞれに付けるかを選べる。
- **ロゴ・すみの文字**: `design.logoImage`（PNGのまま600px以内）・`logoPos`・`logoSize`・`cornerText`・`cornerPos`。待機画面以外のすべての画面に出す（`Viewer.renderDecor`）。
- **問題ごとのテーマ**: `q.themeId`。`Themes.forQuestion(q)` で、セットのデザインの上にテーマを重ねる。背景画像・ロゴ・音はセットのまま。
- **解答者のスマホ**: 書体と、アクセント色を暗くしたグラデーション背景。`design.playerTheme === 'off'` で、書体だけにできる。
